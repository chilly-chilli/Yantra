# Yantra v0.2 开发任务提示词

请在现有 Yantra 项目上实现 v0.2。先阅读实际代码、README、架构文档和测试，再给出简短实施计划并完成开发、验证与文档更新。保持必要改动，复用现有 Google ADK、Pydantic 合约、确定性计算、会话隔离、运行记录和复测能力。

本轮核心目标是：用户提供公司名称或证券代码，以及未经人工结构化的原始材料，系统识别研究标的、解析材料、提取结构化数据与研究证据、主动独立检索、选择投资研究框架、形成投资论点、执行适用的估值与独立核验，最终生成带证据和明确缺口的买方投资备忘录。用户不需要预先编写材料 manifest 或严格 JSON。

本版以 CLI 跑通完整流程为主要验收入口，保留现有 ADK 入口兼容。独立 GUI 在后续版本开发。本轮覆盖 A 股和港股，以小米集团、长鑫科技作为真实研究验收样本；两家均须跑通，最终允许均为 partial。

## 1. 已确定的范围与决策

以下要求作为本轮实施和验收依据。

| 事项 | v0.2 要求 |
| --- | --- |
| 输入与终点 | 公司名称／代码＋原始材料 → 自动解析、独立检索、研究、核验和买方投资备忘录 |
| 市场与样本 | A 股、港股；小米集团、长鑫科技 |
| 使用入口 | CLI 完整流程；现有 ADK 入口兼容；独立 GUI 留到后续 |
| 材料格式 | 文本型 PDF、扫描 PDF、图片、网页、纯文本、Excel、Word、PPT；保留 JSON、CSV 等结构化来源接入 |
| 提取范围 | 财务数据＋经营、行业、竞争、管理层陈述、风险等研究证据 |
| 搜索行为 | 每次研究都主动独立检索，包含补缺口、反对证据、时点内的新变化和市场预期比较基准 |
| 搜索持续性 | 按单次研究需要获取；本轮不建设长期订阅监控服务 |
| 估值交互 | 提供自主运行、人工确认两种模式，默认自主运行 |
| 缺口与冲突 | 自主补查，保留未解决问题，允许交付 partial；不强制等待用户补资料 |
| 全局时间 | 单个完整研究任务总耗时不超过 2 小时，包括全部 Agent、材料处理、检索、计算、核验和收尾 |
| 模型费用 | 单次研究全部模型调用费用合计低于人民币 50 元；搜索／财经数据服务费用另算 |
| Agent 层级 | 最多三层，主 Agent → 四类专业 Agent → 临时子 Agent |
| 第三层角色 | 按任务动态定义，不把角色类型写死；不能继续创建第四层 |
| 创建权限 | 专业 Agent 在主 Agent 授权的任务范围内，自主创建第三层子 Agent |
| 横向协作 | 直接通信、读取获准共享的成果和必要上下文；跨 Agent 转交任务须经主 Agent 批准 |
| 最终核验 | 核验 Agent 对 completed 的否决权不可被主 Agent 覆盖；partial 如实标注未通过项 |
| 数据服务 | 默认用公开来源实际跑通；需要账号、订阅或 API 密钥的服务预留适配接口 |
| 框架使用 | 每次一个主框架，其他框架用于反证检查或补充视角 |
| 用户框架 | 接受自然语言或 Markdown，转换为经校验的内部结构并保留原文 |
| 框架迭代 | 调整形成持久化新版本，经独立核验后供后续研究选择使用 |
| 初始框架 | 价值与安全边际、经营质量与现金流、经营改善与预期差 |

本轮保留现有 DCF 方法的适用范围，不扩展银行、保险、持续亏损企业等的完整估值模型库。研究接入范围与估值方法适用范围分开：样本不适合现有 DCF，或估值依据不足时，继续完成可支持的研究部分，明确模型限制并输出 partial。不能拒绝整个研究来绕过样本验收，也不能为了给出目标价强套不适用模型。

完整 memory 系统属于后续版本。本轮只实现框架配置的持久化与版本管理，以及研究运行、暂停恢复和复测所需的状态保存。

## 2. 默认行为与实现边界

- 默认研究期限沿用现有入口的 12 个月，用户指定时覆盖。
- 默认资料截止时间采用研究启动时点，保存时区和时间；用户指定历史截止时间时，严格按信息公开时间过滤。报告期间、披露日期、价格时间、汇率时间分别记录，不能用财务数据所属期间代替信息可获得时间。
- 用户可以通过 CLI 提交文件、材料目录和网页链接。具体参数命名根据现有代码确定，并提供经实际运行验证的命令示例。
- 公司主体或上市证券存在歧义时，在正式研究启动前确认市场与具体证券；可通过明确的 CLI 参数消除歧义。资料缺口处理与标的身份确认分开。
- 自主模式下，Agent 提出估值参数和依据，程序校验合约、来源口径、方法适用性和预算后授权确定性计算，再接受最终独立核验。
- 人工确认模式下，关键估值假设须获用户明确确认后计算。等待不能被视为批准；确认模式、授权来源和假设版本必须可追溯。
- 两种模式都保留用户查看进度、修改假设、取消和恢复的能力。参数修改形成新版本，使受影响的旧成果失效并重新计算、核验。
- 框架调整可保存为草稿，通过独立核验后才成为后续可选择的新版本。其他运行的新版本不能静默改变已经启动的研究。
- 为失败、等待、取消和恢复明确终态及时间口径。人工等待也受本次运行的全局截止时点约束；超时应收束已有成果，不能自动批准尚未确认的假设。恢复同一次研究不能重置预算。
- 优先采用简单实现，不为未来 GUI、memory、部署或多用户平台提前建设额外系统。

## 3. Agents–Subagents 架构与协作

保留主 Agent 和四类专业 Agent：资料与财务、投资逻辑、估值、核验。扩展局部委派和横向协作，保持程序控制器对权限、预算、版本和终态的控制。

1. 专业 Agent 根据任务创建临时子 Agent。角色由目标、指令、可用工具和完成条件定义，不能将第三层限制为固定职业枚举。
2. 临时子 Agent 只能使用父任务授权范围内的工具与数据，不能通过改名或重新包装任务扩大权限。最多三层、禁止第四层由程序执行。
3. 获准共享范围内的通信、成果读取和必要上下文共享无需逐次向主 Agent 申请。未授权的材料和上下文仍不可读取；不能默认共享完整聊天历史。
4. 跨 Agent 转交或指派任务须经过主 Agent 的内部审批。申请说明任务、接收方、目的、输入引用、完成条件和预算；程序验证批准及剩余额度后执行。
5. 通信和任务转派分开建模。通信不能隐含创建新任务、转移责任或扩大工具权限；需要对方执行新任务时走审批流程。
6. 结构化任务及成果包记录父任务、发起方、执行方、层级、授权范围、假设／框架版本和预算。共享内容、任务归属、修改及审批保留记录。
7. 主 Agent 可以选择框架、调整研究方法及研究标准。标准调整记录旧版、新版、理由和证据，重新核验受影响成果；不能以降低标准掩盖证据不足。
8. 核验 Agent 独立判断证据、口径和结论。主 Agent 不能覆盖否决、伪造通过标记，或将未通过部分写成确定结论。
9. 原始来源追溯、确定性计算、事实与假设区分、禁止编造数据及全局预算是程序保障，不能被模型修改标准绕过。

临时子 Agent 和协作必须实际参与 ADK 执行，产生可检查的任务、工具或事件记录。保持运行间隔离，避免在并发会话中修改共享 Agent 实例的任务上下文或动态子 Agent 列表。

## 4. 原始材料解析与结构化信息提取

建立“接收原始材料 → 解析正文及表格 → 提取财务字段与研究证据 → 规范化 → 合约校验 → 证据登记”的流程。提取需求由当前框架与任务决定，同时保留统一的来源和口径属性。

### 4.1 必须实现的材料能力

- 实际支持文本型 PDF、扫描 PDF／图片 OCR、网页正文、纯文本、Excel、Word、PPT，以及来源提供的 JSON、CSV 等结构化数据。不能将 OCR 或办公文档仅留成空接口。
- 对中国／香港研究常见的中文、英文文字和表格提供可验证的解析路径。支持范围以代表性样本实际验证；复杂版式失败须明确记录，不能宣称所有文档均能准确解析。
- 文件接入包括正文及表格提取。图表内容无法可靠识别时列明缺口，不能凭视觉印象补出精确数字。
- 移除生产路径对人工 manifest、固定行号、固定英文字段映射和简单“字段: 数字”格式的依赖。旧格式可继续服务于离线演示和固定测试。
- 解析失败时自主尝试可用替代解析或来源，并在预算内补查；不能要求用户先整理成严格 JSON 才能研究。

### 4.2 结构化输出与来源

- 财务记录保存字段名称、原始值、规范化值、币种、单位、报告期间、合并口径、披露日期、重述版本、来源及定位。处理中英文名称、括号负数、千分位和表格单位说明。
- 研究证据覆盖业务构成、经营指标、行业情况、竞争信息、管理层陈述和风险信息；保存出处、日期、适用期间、信息类型及相关研究问题。
- 区分可核验事实、假设、预测和分析判断。管理层陈述保留主体与原文归属，不能自动视为已证实事实；数值预测不能混入历史财务记录。
- 采用严格合约及统一元数据，业务字段可扩展，避免把所有研究需求锁死在演示字段列表。
- 保存原始文件或响应快照、内容哈希、来源 URL、获取时间，以及页码／表格／单元格／幻灯片／图像区域／网页片段等定位信息。不能只有转换后 Markdown 的出处。
- 规范化和派生值保留原始值、转换过程及计算引用。字段必须能回到原材料核对。
- 无法可靠提取的值留空并登记缺口；冲突保留来源、口径和候选值，交研究及核验处理。禁止以零、演示值或模型记忆填补缺失数据。
- 解析、字段提取、口径规范化和经济判断分别验证；格式转换成功不代表数字及财务口径正确。

## 5. 搜索研究与数据源接入

实现当前即可使用的公开资料路径，提供统一的数据源适配边界。数据服务凭据与模型服务凭据分开配置。

每次研究都主动独立检索，即使用户材料齐全也要寻找反对证据、时点内的新变化和预期比较基准。综合财务报告、公司公告、行业数据、新闻、行情和估值相关信息，不能只补齐已有论点的支持材料。

- 支持通用网页发现、官方披露定向获取和缺口驱动查询。分别验证 A 股与港股实际可用的资料路径，不能仅增加市场枚举就宣称覆盖。
- 搜索结果用于发现来源，关键事实回到原始披露或可核验的数据发布方。优先评估监管／交易所披露、公司投资者关系材料和行业数据发布方。
- RSS／Atom 可辅助发现公告和新闻，按单次研究需要读取；不建设后台持续监控和定期更新系统。
- 保存查询、获取时间、来源及正文快照，处理重复材料、转载、过期资料和互相引用造成的重复印证。
- 价格匹配具体证券，记录时间、币种和来源；汇率记录日期、方向和来源；市场预期基准记录定义、来源和时点。
- 缺少直接共识数据时，可提出有依据的其他比较方法并接受核验，或明确保留缺口；不得将模型猜测称为市场共识。
- 默认使用公开来源。未配置账号或 API 服务时明确其状态，仍能完成基础联网研究；外部服务的调用费用独立记录。
- 采用必要的缓存、退避和来源切换，避免原样重复失败操作。资料覆盖不足时在预算内调整路径，无法解决则保留缺口。
- 固定快照、演示数据和搜索接口声明都不能代替真实联网获取及内容读取。

## 6. 有界研究循环、费用和停止条件

运行闭环为：核验提出具体问题 → 主 Agent 分析原因 → 调整查询、数据源、分工、方法或有依据的研究标准 → 补查／修复 → 再次独立核验。

研究受全局预算约束，不能持续运行直到通过而忽略时间或费用，也不能反复等待用户补资料才能交付已有成果。

### 6.1 全局时间与模型预算

- 单个完整研究任务总耗时不得超过 7200 秒（2 小时），全部模型调用费用合计必须低于人民币 50 元。为取消活动任务、持久化和报告生成预留资源，在硬上限前主动收束。
- 所有主 Agent、专业 Agent、临时子 Agent、框架解析／调整、模型辅助提取、核验、修复和重试共享同一预算。创建子任务、换框架、修改假设或自动续接均不能另起预算。
- 时间以本次研究启动后总墙钟时间统计，不通过串加并发任务时长替代，也不能仅统计模型调用时间。截止时点持久化，恢复同次研究沿用原截止时点。
- 模型请求执行前保守预留费用，结合输入量、输出上限及配置的单价限制请求；返回用量后结算。并发请求的预留必须原子化，避免各自认为余额充足而超支。
- 返回用量缺失时保留保守预留，不能记为零。模型费以人民币预算管理；其他计价币种保留换算依据和时点，禁止写死汇率。
- 现有固定每调用预留金额不能冒充实际费用。运行记录区分预留、基于用量与单价的费用核算、实际账单可得性；可靠预算控制所需的价格和计费配置应在启动前校验。
- 搜索／财经数据 API 费用不计入模型 50 元上限，单独记录。默认公开来源路径仍须可用。
- 合理调整旧的工具、模型决策、主循环和修复次数上限，适配混合材料及嵌套委派。保留有效的局部限额、超时、并发控制和重试约束，不沿用无限研究要求。

### 6.2 收束与终态

- 预算不足、到达停止边界、无法继续获得可靠证据或能力不足时，自主收束，并说明已完成部分、剩余缺口及停止原因。
- 有可用数据和研究成果但未达到完整研究标准时输出 partial；没有可用成果时输出 failed。用户取消时输出 cancelled。只有独立核验通过当前版本且程序条件满足时才能输出 completed。
- 缺少价格、共识或必要估值输入时，不编造建议、评级或目标价。可保留证据支持的论点及待验证假说，明确不确定性。
- 核验否决 completed 不等于必须无限重试。partial 中未通过项要清晰呈现；已知错误不得作为确定事实或有效计算输入继续发布。
- 主 Agent 调整标准仍需版本记录及独立核验。不能通过删除必要字段、改写状态或降低标准，把本应 partial 的成果标为 completed。
- 用户能够查看进度、主动修改和停止。停止后取消或收束活动任务，保存成果及原因。
- 状态持久化支持故障恢复和复测，避免重复发布框架版本、重复消费预算和混用失效成果。
- 单次请求超时、限速和退避服从剩余全局时间，不能在报告收尾时继续无限重试。

## 7. 多套投资研究框架

框架保存为可配置、可版本化的分析规则，针对公司的投资论点由本次研究生成。

| 初始内置框架 | 主要分析方向 |
| --- | --- |
| 价值与安全边际 | 可追溯的现金流估值、价格与估值差距、假设变化对结论的影响 |
| 经营质量与现金流 | 盈利质量、现金转化、竞争优势及持续性、支持与反对证据 |
| 经营改善与预期差 | 经营改善的证据及持续性、当前价格或可获得的市场预期是否已经反映改善 |

每个框架至少表达适用范围、研究问题、证据需求、风险、反证条件和跟踪指标。每次选择一个主框架，其他框架用于辅助检查。用户指定时按其指定；未指定时由主 Agent 选择并记录理由。选择框架不等于获得对不适用估值方法的授权。

用户通过自然语言或 Markdown 提供自定义框架，系统保存原文、解析结果和校验结果，无需用户填写严格 JSON。

允许 Agent 调整内置或自定义框架，持久化为新版本，保存基线、父版本、修改内容、理由、适用范围、来源运行和核验结果。通过核验的版本供后续研究选择；不能把本次公司的具体事实写成所有公司通用规则。

框架版本、研究标准版本、估值假设版本分别追踪。版本变化使受影响成果失效并重新分析、计算或核验；复测使用原运行的版本和材料快照。框架调整、校验和写回也计入本次模型预算。

## 8. A 股、港股适配与现有实现修正

先核对代码，再修复与本轮目标直接相关的约束：

1. 分离公司主体与上市证券身份，保存市场、交易所、证券代码／类别及挂牌关系。财报、价格、股数、交易单位和每股价值匹配正确主体及证券。
2. 解除人民币和固定金额单位的硬编码，保存报表币种、交易币种、原始单位和转换依据，区分单位换算与汇率转换。
3. 核验不同股份类别、跨市场挂牌及交易单位等所需的股数口径，不能将公司总股数与任一交易单位直接混用。
4. 规范财政年度、年度／中期等期间、披露日期和重述版本，移除固定年份白名单及演示性的字符串排序逻辑。
5. 从真实财报建立与现有 FCFF DCF 一致的现金流口径及调节依据，不套用演示材料对经营现金流、利息和税盾的约定。依据不足时补查或保留估值缺口。
6. 对验收样本实际判断 DCF 适用性；需要周期调整或缺少可靠长期假设时明示限制。保留确定性估值及情景／敏感性计算，对不适用部分输出 partial，不将新增完整估值模型库作为本轮必达范围。
7. 报告摘要、论证和引用来自本次成果，移除所有模式共用的固定摘要及只展示演示行号的引用过滤。
8. 将原有强制人工确认改为两种显式运行模式。自动授权和用户确认分别记录，不能仅修改 confirmed 字段来伪造确认来源。
9. CLI 实际贯通文件／目录／链接接入、模型配置、框架选择、预算、进度、参数修改、取消、恢复及报告输出；ADK 入口复用同一流程和权限边界。

保留现有八部分备忘录：投资结论摘要、投资逻辑、事实与数据基础、财务分析与估值、风险因素、反向验证条件、持续跟踪指标和市场预期差。某部分证据不足时明确写缺口。报告保存框架、标准、假设版本，价格时点、关键证据及计算引用；同步产出可读 Markdown、结构化 JSON 和计算凭证。

## 9. Google ADK 与开源选型

遵循实际安装版本的 Google ADK 规范，优先复用原生 Agent、工具、Runner、事件、Session／State 和回调机制。核对该版本的委派、取消、恢复及文件／成果管理能力，必要时阅读对应源码；不要无条件升级或重写架构。

会话状态可序列化，通过 ADK 支持的上下文和事件机制更新。专业任务与动态子任务保持必要隔离，权限、层级、预算和版本由程序执行。现有 ADK 入口应参与实际运行验证，不能只展示结构图。

构建每个新模块前，评估成熟 GitHub 项目能否直接依赖、经适配器接入或作为设计参考。简要记录维护情况、许可证、依赖及运行成本、来源定位能力、格式／数据覆盖、离线与联网要求、与现有项目的契合度，选择满足需求的最小方案。

下表列出候选入口，供实施时核实版本和接口，不表示已经集成，也不要求全部采用：

| 模块 | 候选／参考 | 评估重点 |
| --- | --- | --- |
| 文档转换 | [MarkItDown](https://github.com/microsoft/markitdown) | 多格式转换、办公文档及原始来源定位的保留 |
| 文档／表格与 OCR | [Docling](https://github.com/docling-project/docling) | 布局、表格、OCR 路径及结构化定位；核实满足本轮实际 OCR 要求的组合 |
| 搜索发现 | [DDGS](https://github.com/deedy5/ddgs)、[SearXNG](https://github.com/searxng/searxng) | 可替换搜索后端、默认路径的可运行性与部署成本 |
| RSS／Atom | [feedparser](https://github.com/kurtmckee/feedparser) | 按需解析信息源，辅助发现来源 |
| 财经数据 | [AKShare](https://github.com/akfamily/akshare) | 逐一核验 A 股、港股接口、时点、口径和上游来源 |

格式转换与 OCR 是不同能力，不能仅因库支持文件转换就认定 OCR 和表格提取已经完成。依赖项目的输出仍须接受 Yantra 的来源、财务口径和证据核验。只安装库或声明空接口不能算完成模块。

## 10. 验证与发布验收

先运行并理解现有测试。更新确实被本轮替换的行为，保留会话隔离、权限控制、版本失效、确定性计算和复测等有效保障。测试覆盖实际风险及行为变化，避免只验证实现细节。

发布验收与单次研究的 completed 状态分开：小米、长鑫两家真实公司的完整流程都跑通，即使最终均为 partial，也可通过本轮发布验收；仍必须完成下列模块和边界验证。

| 验证对象 | 必须观察到的结果 |
| --- | --- |
| 两家真实研究 | 通过 CLI 提交公司及真实原始材料，实际解析、独立联网检索、真实模型分析、适用计算和核验，生成可检查的成果及运行记录 |
| partial 最低质量 | 每家都有实际提取的财务记录与研究证据、可定位引用、证据支持的分析和明确缺口；读取全部失败或空泛模板不算跑通 |
| 文件格式 | PDF、扫描件／图片 OCR、网页、文本、Excel、Word、PPT 及结构化来源各有代表性验证，数字及出处可人工核对 |
| 财务与研究证据 | 财务字段和定性证据均可提取；处理期间、单位、币种、负数、口径、陈述归属及冲突；缺失值不变成零或虚构值 |
| 独立检索 | 用户材料齐全时仍发起独立检索；可观察到反证、时点内变化和预期基准的查询及获取结果，或如实记录未找到 |
| 标的与市场 | 歧义输入在启动前得到处理，A 股／港股主体、行情、股数及币种口径一致 |
| 外部服务未配置 | 未配置私有资料服务时，默认公开来源及实际解析路径仍能运行；OCR 不以空接口替代 |
| 第三层委派 | 专业 Agent 实际创建至少两种临时角色并执行；第四层及越权工具调用被程序阻止 |
| 横向协作 | 获准范围内直接通信和读取成果；未经主 Agent 批准的跨 Agent 转派被阻止；批准后任务及预算归属可追溯 |
| 自主与确认模式 | 默认自主研究不强制等待估值确认；人工模式只计算已明确确认的当前版本；修改、取消及等待超时行为正确 |
| 预算与收束 | 用受控时钟及费用用量验证并发预留、重试、子任务、框架调整和恢复共同计费；接近全局上限能及时保存并正确终止 |
| 费用口径 | 模型费低于 50 元的控制独立于搜索／数据服务费用；缺失用量不记零，预留和费用核算可检查 |
| 核验与标准调整 | 主 Agent 无法覆盖否决；标准变化有版本及重新核验；未通过成果不变成 completed |
| 框架选择与写回 | 三套框架可选择，自然语言／Markdown 自定义可解析；修改形成持久化核验版本，历史快照稳定 |
| ADK 与恢复 | 标准应用发现及现有入口可用；动态任务实际执行；并发隔离、保存、恢复、复测和计算复现有效 |

真实联网／模型运行与固定快照测试分别报告，后者不能代替前者。可用真实来源快照及可人工核对的测试材料验证复杂格式；OCR 验证应覆盖实际识别，不能只模拟已识别文本。

核验无通过结果、价格或共识缺失、方法不适用，可以构成 partial 的原因；解析模块未实现、搜索仅占位、预算失控和已知错误被写成确定结论，仍属于开发验收失败。

若环境缺少有效模型配置，先完成其余可执行开发与验证，如实列明真实模型端到端验收未完成。不能用测试模型、虚构材料或离线演示宣称真实研究已经通过。
