# v0.5 更新方案：宿主集成与用户交互

日期：2026-10-14。目标版本：v0.5。
状态：产品范围已确认，具体工程设计为拟议方案；代码实施及本方案验收尚未执行。

本次仅编写方案。后续须由用户明确要求实施；阅读本文不授权收费调用、push、合并、部署或发布。GUI、网页及独立聊天界面不在本轮范围内。

## 1. 目标与相关计划

将 Yantra 定位为可嵌入用户现有 AI 宿主的投研引擎，同时保留直接 CLI。宿主理解自然语言并展示结果，Yantra 负责研究执行、证据、预算、授权、确定性计算及独立核验。研究模型继续由 Yantra 配置和调用，不假设能够复用宿主订阅、模型会话或费用额度。

完整交互目标：用户提交研究 → 取得研究标识 → 离开当前调用 → 再次查询 → 读取带核验状态的报告及依据 → 修改假设 → 读取新版本及差异。CLI、Skill、本地 MCP 均须在 v0.5 交付；分阶段开发不意味着将 MCP 移出本版。

与现有 [v0.5 自主研究与数据服务实施计划](../prompts/v0.5-implementation-plan.md)互补：该计划负责名称输入、公开资料获取、研究判断、正式／演示入口分离和数据服务；本文负责对外调用、生命周期、安装和宿主交互。不新增供应商，不把计划中的能力写成已实现，不覆盖已有计划。

首次设置及自主研究授权由统一业务层处理。既有计划提出的默认自主策略与历史问卷要求存在差异，按已确认业务计划统一解决；Skill／MCP 不得另行伪造同意、写入永久授权或绕过明确拒绝。实施时如两份计划出现尚未解决的冲突，指出具体冲突并澄清，不静默选择。

实施前读取 [项目 README](../../README.md)、[文档索引](../README.md)、[工程规则](../../AGENTS.md)、[使用指南](../USAGE.md)、[能力配置](../CAPABILITIES.md)、[架构说明](../ARCHITECTURE.md)、[ADK 边界决策](../decisions/0002-adk-native-boundaries.md)和[评估入口](../../tests/eval/README.md)。核对分支、Git 状态和固定依赖，保护其他任务未提交的文件。

## 4. 执行前能力与权限检查

在开发 Agent 实施前、用户宿主首次接入时，分别检查实际执行环境。检查结果只陈述真实能力，不把“用户愿意开放权限”写成“当前已经具备全部权限”。

1. 检查是否提供命令执行工具，能否启动 Yantra、读取配置及获准材料、写入指定研究目录。
2. 区分工具不存在、工具存在但权限被拒绝、可执行文件缺失、依赖缺失、路径不可见和配置错误，给对应修复方式。
3. 单独检查所需网络及凭据是否可用。默认本地诊断不发起研究或收费模型调用；联网探测单独标记。
4. 检查宿主运行在本机、容器还是远端。不能假设宿主中的路径就是 Yantra 服务所在机器的路径。首版只支持实际验证的共享本地路径配置；不可见材料明确报错，不承诺自动上传。
5. 检查长任务执行者能否在宿主工具调用结束后继续存在。后台进程若会被宿主回收，采用经验证的本地执行入口，不以 shell 后台启动即视为生命周期问题已解决。
6. Agent 有命令行权限时可使用 Skill＋CLI；没有命令行权限但已配置 MCP 时可使用 Skill＋MCP。两者均不可用时返回具体接入步骤，不虚构执行成功。
7. 用户已表示愿意开放完成任务所需权限，不反复索取同一授权；实际平台阻止执行时说明受限动作及所需设置。不能绕过平台限制，也不把执行权限扩大为付费、对外发布或全部业务授权。

权限检查是实际执行条件检查，不要求全盘访问或全面关闭保护。只配置当前工作需要的路径、命令及服务。

## 5. 统一对外契约

CLI 与 MCP 复用同一业务入口、状态及费用账本。Skill 只指导调用，不承担核心验证。先检查现有代码，仅提取实际需要复用的逻辑，不新建通用框架。

下表为拟议操作语义，不是现有命令或最终 MCP 工具名。

| 操作 | 输入与输出要求 |
|---|---|
| 能力发现／配置诊断 | 接口版本、可用操作、缺失项及修复指引；本地检查与真实服务探测分开。 |
| 提交研究 | 目标、问题、可选材料、预算及业务授权；持久化后返回 run_id 和提交收据，不等待完整研究。 |
| 列出／查询 | 分页定位研究，返回阶段、实际进展、缺口、待处理事项、预算和允许的后续动作；不调用模型。 |
| 读取报告／依据 | 按研究、产物及版本读取，携带核验／授权状态、来源定位和哈希；大内容有限读取并明确范围。 |
| 回应选择／修改假设 | 绑定待处理事项和预期版本；区分已接受、已应用、已拒绝，重算及核验受影响成果。 |
| 取消／恢复 | 区分请求接受与实际停止；恢复检查原预算、截止及未知外部操作，不隐式重放。 |

复用现有 JSON 包装和退出码语义；破坏性变更必须有版本与迁移说明。schema 从实际校验结构导出或复用，避免独立手写两套定义。研究 partial／failed 与查询失败分开；MCP 传输错误、业务操作错误和研究结果状态分别映射。

next_actions 不是授权。摘要和机器字段来自同一结果，不能把“暂定”“未核验”从摘要中删去。保持旧任务查询、恢复、重放及历史算法的兼容行为。

## 6. 长任务、幂等与恢复

- 先检查固定 ADK 2.11.0 的执行、Session、事件及生命周期能力，再设计最小本地执行方案。若补充进程管理，记录具体能力缺口、业务必要性和外部行为测试；不升级 ADK 或引入分布式任务平台。
- 明确请求已持久化、执行者已启动和研究运行中的区别；启动失败不能永久显示正常运行，连接断开不等于用户取消。
- 提交支持持久幂等标识，定义作用域、规范化请求摘要和保留规则。同标识同请求返回原研究，同标识不同请求报冲突。并发和响应丢失不能创建第二项研究或重复预留费用。
- 提交去重不证明外部调用 exactly-once。沿用 in_flight_tool 和未知结果恢复限制，不因重新连接重放可能收费的操作。
- 本地执行环境仍存活时，宿主或 MCP 连接结束不终止已接受任务。机器重启后能找到记录并报告真实中断／可恢复状态；不要求开机自动恢复，也不假装断电期间继续运行。
- 保持单一业务状态写入者及运行锁。执行者存活信息属于观测，不建立另一份研究状态或费用账本。
- 修改和确认绑定版本，处理并发冲突及重复响应；不能覆盖另一入口刚提交的修改或无意重复生成版本。
- 恢复保留原截止和预算，预算耗尽时读取成果或明确新建后续研究，不能用“继续”重置限制。旧取消任务的恢复规则保持兼容。

## 7. 安装与配置

复用已有软件包及 yantra 入口，验证安装产物包含必要资源及 Skill 分发文件。在干净临时环境检查依赖和离线示例，不以开发仓库可以运行代替安装验收。

明确配置、研究目录、知识库及凭据定位，保留显式参数和已有环境变量语义。同一配置及存储从不同工作目录调用仍能找回任务。若改变默认目录，提供显式迁移和旧路径兼容，不自动扫描、合并或搬迁用户凭据。

首次设置支持结构化配置和宿主引导，也保留直接 CLI；非 TTY 调用不进入输入菜单。凭据在本地填写或以环境变量引用，不要求复制到对话、Skill 或工具响应。配置有效、服务可连接和真实研究通过分别报告。

Yantra 内部费用和宿主费用分开说明，不能声称能够读取或控制宿主账单。已有明确偏好和授权不重复询问。

## 8. Skill 与本地 MCP

### 8.1 一个主要 Skill

覆盖触发场景、能力检查、需求整理、提交、查询、读取、修改、取消、恢复及错误处理。只追问影响结果的身份、授权或关键缺失项。内部 finance、thesis、valuation、verification 不分别变成必须由宿主拼接的流程。

要求宿主保留 provisional、partial、资料缺口和核验否决的含义，不把暂定情景概括为正式目标价。指令不能保证模型遵守，因此结果资格也须由引擎字段表达，并通过实际宿主场景检查。

宿主安装其他 tools／skills／MCP 不意味着 Yantra 自动继承权限。扩展继续通过配置、角色授权和冻结快照接入；来源正文和工具结果不得充当新授权。

### 8.2 本地 MCP

首版建议 stdio，实现所需工具发现和调用，不默认实现远程多租户、OAuth 或 MCP UI。核对固定 SDK 和两宿主能力，明确工具输入 schema、输出、错误及版本。

MCP 会话关闭与研究生命周期解耦；查询不触发隐式恢复。成果通过获准研究和产物标识读取，拒绝路径越界，不暴露任意本机文件。

本地可信客户端边界应明确，不能把 user/session 字段当作身份认证。既有 ADK 所属 Session 约束不得被新入口无意绕过；明确允许共享的本地工作区和会话映射，跨入口操作经过统一访问规则。

### 8.3 Codex 与 OpenCode 验收

分别核实两宿主当前实际安装版本、Skill 加载方式、命令执行权限和 MCP 配置方式。以本机环境和正式文档为准，不从产品名称推断兼容性。

记录两条调用路径的可用性：Skill＋CLI，以及 Skill＋MCP。验证命令行受限而 MCP 可用的降级场景，不能把宿主有自然语言聊天能力当作能执行工具。

默认不修改其他宿主配置。安装说明和实测记录包含版本及权限条件；缺少某宿主环境时完成其余工作并标记该宿主未验收，不能宣布两宿主均通过。

## 9. 追问、版本与新增材料

- 依据追问读取原报告及获准原文定位，区分原文、推断和假设；新搜索结果不能静默替代旧依据。
- 假设修改保存原版本、新参数、依据和授权来源，失效受影响成果，再重算与独立核验；指定版本读取不能返回最新版冒充。
- 核对现有 Artifact 指针及文件覆盖限制：被承诺可追溯的版本须保留稳定内容；缺失或改写明确失败，不能用旧索引假装历史字节仍在。
- 新财报建议创建关联原研究的新任务，重新确定截止、预算和来源适用性。首版至少返回明确流程，不把新增材料当成无影响的恢复；具体接口在实施前固定。
- 长期偏好只保存用户明确要求长期保留的内容，单次修改不自动升级为永久规则。
- 本轮不要求发布各研究模块的独立 Skill。已有知识读取和复算按闭环需要复用，不扩展成通用工具平台。

## 10. 实施顺序及最低验收

| 阶段 | 交付 | 检查 |
|---|---|---|
| A：契约与生命周期 | 共享入口、schema、提交／列表／查询、幂等、执行和恢复 | 并发重复提交、响应丢失、进程退出、预算不重置、旧 CLI 回归。 |
| B：安装和 Skill | 干净安装、能力／权限诊断、成果读取、主要 Skill | 非 TTY 无阻塞、跨目录定位、凭据不泄露、固定版本可追溯。 |
| C：本地 MCP | 工具发现、参数和结果映射、访问边界、会话解耦 | 真实本地协议连接及重连；CLI／MCP 状态和费用一致。 |
| D：宿主与交付 | Codex＋OpenCode 接入、追问修改、文档及验证记录 | 实际宿主调用、限制保留、版本冲突、取消收束、重新找到任务。 |

A—D 全部属于本方案 v0.5 范围，可阶段性提交，不能以 B 完成代替全版交付。自主研究计划尚未落地时，可用合成材料验证接口，但须明确依赖；名称输入的完整产品验收仍需相应研究能力可用。

最低行为场景：

1. 同一幂等请求顺序／并发提交及响应丢失后重试，只创建一个研究；冲突输入明确拒绝。
2. 宿主断开后可查询；执行者异常退出不假报运行，跨重启保留预算、截止和未知操作限制。
3. CLI／MCP 交替读、改、取消同一任务，无重复费用、越权或静默覆盖。
4. 查询失败研究仍是成功读取；partial／暂定结果保持限制；取消请求接受不冒充实际停止。
5. 过期确认、旧版本修改和重复操作有明确结果；用户拒绝不被 Skill 默认流程覆盖。
6. 指定版本报告和证据可核对哈希，缺失、篡改及路径越界明确失败；有限读取不伪装完整。
7. 缺凭据、缺依赖、无命令工具、权限拒绝及路径不可见分别诊断；无命令行但 MCP 可用时仍能使用。
8. Codex 和 OpenCode 分别完成研究、查询、报告读取及一次假设修改，正确展示研究标识、版本和核验状态。

分别记录确定性测试、离线模型替身、真实本地 MCP 协议、真实宿主交互、真实联网资料、研究模型和 judge 评估。离线测试阻断未模拟网络；真实调用须有明确凭据、服务范围和总预算，宿主付费调用也纳入范围说明。没有真实环境或授权则明确未验证，不把接口测试写成研究质量通过。

## 11. 非目标和交付要求

非目标：GUI、网页、独立聊天前端、云部署、远程多租户、订阅监控、宿主模型替代内部模型、自动继承任意工具权限、通用插件市场、新估值方法和新数据供应商。

实施后按实际改动更新 USAGE、CAPABILITIES、ARCHITECTURE、README／索引及 Unreleased；验证证据放在 docs/validation/实际版本/。本次方案不把未来接口写成现行能力，不提前修改项目版本，也不改写历史验证。

按仓库规则阶段性提交，暂存本任务文件／片段，完成相关检查及 git diff --check。不纳入其他任务改动、凭据、用户材料或输出。最终报告真实修改、验收、限制及 commit／push 状态；未经授权不 push。
