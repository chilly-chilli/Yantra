二、记忆层次与基本原则

区分以下内容：

1. 任务工作记忆
保存当前计划、提取候选、临时假设、待办和核验过程，用于推进、恢复与运行归档。

2. 项目共享知识
保存原始资料、提取事实、关键论点、待核验问题、冲突、更正关系及研究快照，支持跨 session 检索。

3. 用户明确要求与偏好
保存用户明确要求长期记住的全局或特定公司要求。普通任务指令默认只影响本次，不自动推断偏好。

基本原则：
- 归档、核验通过、允许跨任务检索、适用于本次研究是不同属性。
- 未核验、被否决及人工修改内容可以保存，但不能因此获得正式证据资格。
- 旧判断只作线索，本次投资结论和估值判断独立形成并核验。
- 不因“最新”而静默解决冲突。
- 分别记录报告期间、披露时间、研究截止时间、获取时间和记录时间。
- 保留历史版本，固定旧研究使用的引用。
- 记忆操作遵守现有权限、预算、取消、恢复和核验否决机制。
- 程序执行访问和提交权限，不能仅依赖提示词。

三、职责分工

主 Agent：
- 提出研究问题、资料缺口和检索任务；
- 决定证据需求和检索范围；
- 基于本次证据形成判断；
- 提议事实、论点、问题和状态变更。

检索与知识模块：
- 先查共享知识库，再按任务获取外部资料；
- 获取原文、归档、去重、索引和检索；
- 返回来源定位、版本、日期、核验及适用状态；
- 管理读取记录、修改提议和版本关系；
- 不自行批准事实或投资结论。

现有解析模块：
- 解析材料和提取事实；
- 保留页码、表格、单元格等原始定位。

现有独立核验模块：
- 事实：检查来源、提取和口径；
- 论点：检查推理、假设、支持证据和反证；
- 问题：检查其依据及后续核查价值，不把未知答案标为已证实；
- 核验论点状态变更和实质修改。

控制器：
- 执行权限、预算、版本及提交检查；
- 根据核验结果提交正式更新；
- 研究 Agent 不得自行批准自己的提议。

四、存储与数据合约

采用本地文件目录＋SQLite：
- 文件保存原始字节快照、解析内容和完整报告；
- SQLite 保存正式结构化记录、不可变修订、引用关系、核验记录和操作记录；
- 全文及向量索引是可重建的派生数据，不能成为唯一证据存储；
- 向量本地持久化，首版不引入独立向量数据库服务；
- 使用数据库事务及现有原子文件写入机制，保持引用完整性。

结合现有合约定义最小必要字段：
- 条目 ID、修订 ID、基准版本及所属 session；
- 公司身份、证券代码、市场、交易所和股份类别；
- 行业或研究主题关联；
- 来源 ID、URL/路径、原始字节哈希和定位；
- 报告期间、披露时间及依据、获取和记录时间；
- 财务数值、币种、单位和合并口径；
- 核验状态、核验依据和被核验内容哈希；
- 当前使用范围及本次适用性判断；
- 支持证据、反对证据、关键假设和失效条件；
- 更正替代、冲突、否决及删除关系；
- 人工修改记录；
- embedding 模型标识、配置指纹、维度和索引版本。

公司与证券身份分别管理，避免合并同名公司或混淆不同股份类别。

知识引用使用稳定条目 ID＋修订 ID；证据引用使用来源 ID＋字节哈希＋定位，不能仅依赖文件名。

相同内容可共享底层文件，但保留各渠道、获取记录和 session 引用。重复获取不能算作多份独立证据。

五、自动归档与重点记忆选择

原始资料、提取结果、历史论点和问题自动归档，保留真实状态。

吸收提案中的重点记忆规则，用于决定启动摘要及优先检索内容：
- R1：支撑或反驳关键投资论点；
- R2：影响估值适用性、关键输入或主要风险；
- R3：解决已有问题或形成有依据的新问题；
- R4：纠正旧记忆或解释冲突。

记录规则 ID 和具体理由。未命中规则的资料仍可归档和按需检索，不自动加载进启动摘要。

工作计划、临时推理和普通日志默认保留在运行档案中；不默认进入跨 session 证据检索。

区分重点候选与已核验重点条目：
- 待核验论点只能作为线索；
- 被否决论点保留否决理由；
- 问题可进入待办，但不表示其答案已成立；
- 不自动把运行经验升级为通用研究规则。

六、启动加载与事实复用

启动时：
1. 默认关联目标公司的历史资料。
2. 根据本次研究问题检索行业、其他公司及主题知识。
3. 在上下文预算内加载资料目录、关键事实、历史论点和待核验问题。
4. 原文和完整报告按需读取。
5. 标明历史论点的形成时间、证据、状态及适用条件，提示其仅供参考。
6. 明确区分已核验事实、未核验候选、历史判断、人工输入和用户偏好。

历史已核验事实可以复用，但检查：
- 来源完整性及哈希；
- 本次期间、证券身份、币种及口径；
- 资料截止日期；
- 更正披露、冲突及原核验缺口。

发现异常或不适用时重新核验。不必重复解析相同且适用的原始文件。

每次仍主动检查新披露、反对证据及所需市场基准，历史命中不能自动判定资料充分。

七、独立判断快照与历史比较

吸收提案的“形成判断—固定快照—历史比较—补充核查—核验修订”流程，但不执行其隐藏历史论点的阶段规则。

流程：
1. 加载历史线索并开展本次研究。
2. 基于本次证据形成判断，保存不可变判断快照及证据引用。
3. 比较历史关键论点与当前判断，检查未关闭问题。
4. 记录支持、削弱、反驳、范围变化、假设变化或证据不足。
5. 根据差异补充核查。
6. 新核查导致修订时保存新版本，不覆盖比较前快照。
7. 独立核验通过后发布当前结果并提交相应知识更新。

这里的独立判断指证据和核验独立，不声称模型未接触历史观点。

关键论点至少保存主张、支持与反对证据、假设、失效条件及修订历史。可采用 open、supported、weakened、refuted、unresolved、closed 等判断状态；如现有状态体系适用，优先复用。

论点判断状态与核验状态分别管理。研究 Agent 提议状态变化，独立核验后由控制器提交。

不得把不同层级指标混为一谈。例如汽车业务利润率改善但集团利润率下降时，须检查业务范围及其他业务影响，不能直接认定原集团论点成立或被推翻。

八、混合检索

实现元数据筛选＋SQLite FTS5 关键词检索＋embedding 语义检索：
- 先执行公司、证券、期间、日期、类型和使用权限等硬筛选；
- 验证中文关键词检索与短词匹配；
- 语义检索发现表述不同但主题相关的候选；
- 本地计算筛选后候选的向量相似度；
- 合并去重，记录排序规则和匹配依据；
- 保留冲突及反对证据；
- 相似度不能代表正确性、核验通过或证据独立。

按章节、段落和表格边界切分，保留来源定位与上下文，避免拆散表头、单位和数据。

时间过滤：
- 历史资料依据信息可得时间筛选；
- 未知披露时间遵守现有历史截止规则；
- 历史论点须检查形成时间和证据可得时间，不能引入事后修订；
- 新建历史截止研究与原运行 replay 分开处理；
- replay 只读取原运行固定版本，不重做远程判断。

九、embedding 配置与预算

在现有模型配置中心增加 embedding 类型：
- 配置服务地址、模型名称、凭据环境变量及必要参数；
- 沿用凭据管理，不输出密钥；
- 保存模型、配置及索引版本，不混用不兼容向量；
- 仅为新增或实质变更内容生成向量；
- 模型切换重建对应索引；
- 调用计入触发它的 session 费用、时间及请求预算；
- 未知费用不记为零；
- 未配置、调用失败或预算不足时记录降级，继续元数据和关键词检索；
- 独立索引重建也必须有显式预算约束。

保持现有预算上限及费用预留核算机制，不增加隐性无上限调用。

十、并发提交、运行隔离与恢复

同一公司正式知识更新串行提交，并检查基准版本：
- 旧基准不能覆盖新修订；
- 版本变化时返回冲突，要求重新协调提议；
- 锁等待消耗当前任务时间，不重置预算；
- 使用数据库事务和可恢复文件提交记录处理跨存储操作；
- 中断后完成或回滚未结束提交；
- 派生索引更新失败可重建，不能损坏正式数据。

session 固定使用过的知识及证据版本：
- 共享库更新不静默改变当前或已完成研究；
- 新证据须经本次流程接纳；
- 记录受影响成果，沿用失效、重算及重新核验机制；
- 记录检索、读取、采用及重新核验历史知识的过程；
- resume 和 replay 保持原预算、截止日期及版本约束。

completed、partial、failed、cancelled 均归档已获得内容：
- completed：满足当前完成条件；
- partial：有可用成果但有明确缺口；
- failed：无可用研究成果，但可能已有资料；
- cancelled：用户取消并收束。
运行状态不改变各条目实际核验状态。

十一、明确用户要求与偏好

仅保存明确长期记忆指令，不推断用户偏好。通过现有 CLI/ADK 交互入口实现最小的新增、查看、更新和撤销能力。

保存时记录：
- 用户原话及规范化含义；
- 全局或特定公司范围；
- 时间、来源和版本；
- 保存状态与本次任务应用状态。

优先级：
本次显式参数 > 特定公司要求 > 全局默认要求。

要求不能覆盖程序硬约束和核验否决。
- 普通任务指令默认只对本次生效；
- 保存长期要求后回显内容与范围；
- 多家公司导致范围歧义时询问；
- 不用新默认覆盖本次显式参数；
- 用户明确要求修改本次任务时，在调度边界应用；
- 影响框架、期限或计算的变更触发相关成果失效和重新核验；
- 撤销要求保留历史，并重新计算默认值。

不要求实现新的聊天产品或行业级偏好系统。

十二、管理命令及修改删除

沿用现有 CLI 风格提供：
- 查询；
- 查看条目、版本、来源和核验依据；
- 查看库与索引状态；
- 重建全文及向量索引；
- 编辑事实；
- 删除历史证据；
- 管理明确用户要求。

事实编辑：
- 创建新修订，保留旧值、理由及来源；
- 不修改原始快照和旧 session 引用；
- 数值、单位、期间、币种、口径、主张或来源变化撤销旧核验资格；
- 人工输入不继承已核验状态；
- 无原文依据时明确标记人工输入；
- 核验记录绑定内容哈希，不能通过填写 passed 标记自行恢复核验；
- 仅排版变化不应撤销有效核验，采用明确的结构化内容规范化规则。

本版不支持直接编辑数据库或文件并自动回写，不照搬提案的 Markdown 文件监听流程。

删除：
- 默认软删除，退出后续检索和自动加载；
- 保留操作记录，旧 session 仍可追溯固定版本；
- 区分移除 session 引用与删除共享资料；
- 永久删除先展示影响范围，再要求明确确认；
- 检查共享引用，清除相应内容及派生索引，不误删无关资料；
- 受影响研究标记来源缺失、无法完整复现；
- replay 对缺失明确报错，不能伪称成功；
- 自动去重或清理不能触发永久删除。

十三、为 v0.3.1 外部信源扩展预留接口

v0.3.1 将在 web_search 基础上增加其他获取渠道，例如 RSS/Atom、官方披露接口或数据服务。v0.3 只建立必要接口并接入现有路径，不实现订阅调度或新信源服务。

1. 分离资料发现与原文获取：
- 发现接口接收研究问题、目标、截止日期和预算上下文，返回候选；
- 获取接口接收候选，返回原始内容、来源元数据及获取状态；
- 候选支持 URL、外部条目 ID 或其他定位信息，不绑定搜索结果格式。

2. 现有 web_search 使用统一信源适配接口。新增信源不应要求修改核心存储、解析及核验流程。

3. 统一必要元数据：
- 信源及适配器 ID；
- 外部条目 ID、原始和规范 URL；
- 标题、发布时间及依据、获取时间；
- 内容类型及原始内容引用；
- 获取状态和失败原因。
未知值明确标记，不补造。

4. 为增量获取预留不透明游标和检查点存储，支持未来分页、RSS/Atom 进度记录。订阅管理、轮询和自动唤醒留到 v0.3.1。

5. 所有信源共用预算、超时、取消、恢复、归档、去重、截止筛选、解析和核验入口。

搜索摘要、RSS 摘要和接口元数据不能自动替代原文证据；多渠道发现同一资料不算独立证据。

6. 用现有路径及一个离线测试适配器验证可扩展性，不建设通用插件平台。

文档记录接口契约、接入位置及 v0.3.1 待实现事项，区分接口预留与能力实现。

十四、测试与验收

使用新建、明确标识的夹具，不导入 workspace 现有测试材料。至少验证：

1. 两次 session 复用历史资料及适用的已核验事实。
2. 历史论点仅作参考，不直接获得当前结论资格。
3. 固定判断快照后进行历史比较，修订保留依据和旧版本。
4. 论点支持、削弱、反驳和证据不足均有正确状态及核验记录。
5. 业务与集团指标差异不导致错误论点更新。
6. 不同期间并存；同期同口径冲突不自动采用最新值。
7. 历史截止排除未来证据和事后论点修订。
8. 中文关键词及语义检索返回准确来源定位。
9. embedding 增量更新、模型切换、预算及降级有效。
10. 归档不自动改变核验状态，partial 中合格事实可复用。
11. 实质编辑生成新版本并撤销旧核验，旧 session 不受影响。
12. 删除、永久删除和共享引用符合规定。
13. 用户偏好不覆盖本次显式参数，撤销与应用状态正确。
14. 并发提交不丢失更新，旧基准不能覆盖新版本。
15. 提交中断可恢复，派生索引可从正式数据重建。
