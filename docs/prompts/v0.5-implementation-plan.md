## 已确认的首轮目标

用户仅提供公司名称，例如“研究贵州茅台”，Yantra 应自行获取公开资料，按未来 **12 个月**判断当前股价是否值得买。先完成这条完整流程，再根据实际障碍决定内部结构调整。

- 自动使用已有信息工具；调用失败时记录安全的失败原因，并继续尝试适用来源。单次无结果不等于整个来源不可用。
- 仍缺关键资料时，自动搜索或获取公开网页；浏览器补查需要先确认实际可用工具及权限，不能把 HTTP 抓取宣称为可交互浏览器能力。
- 一个可靠来源可以支持初步判断，不以独立来源数量作为硬门槛。继续检查证券身份、日期、单位、来源记录及数学计算。
- 财务依据来自公司公告、交易所披露或可定位原始财报的接口；行情依据须明确证券代码、报价时间及单位；新闻关键事实需定位原始公告或报道。
- 行情请求和完整返回记录可以作为依据，不强制要求网页截图；财报保留原文及页码或相应原文定位。
- 允许自动提出估值假设，无须逐项等待用户确认；区分事实与估计，说明依据，展示较差、一般、较好三种情景。
- “值得买”须考虑安全边际。由模型按风险选择比例并解释；共同规则仅作参考，不设置强制比例范围。
- 达到时间或费用上限后停止查找，返回已有成果及缺口。关键缺口可能改变买入判断时，明确说明目前不能形成该判断。

## 已确认的入口分离要求

将正式研究入口和演示入口分开：

| 入口 | 目标行为 |
|---|---|
| `start` | 正式研究；允许仅给公司名称启动，不再因缺少 `--material` 自动进入演示流程。 |
| `demo` | 显式启动演示；使用明确标记的虚构资料和固定离线策略，不执行真实检索或模型调用。 |

实施要求：

1. 先分开命令入口，再按必要性移动演示专用代码。仅移动文件不能替代入口修正。
2. 保留有用的离线演示、受控测试及旧任务重放能力，不直接删除正式研究仍依赖的公共引擎功能。
3. 检查旧 `start --mode offline-demo`、`--materials-dir`、恢复及重放调用的兼容方案；在最终提示词中明确迁移行为，不静默更改历史运行记录。
4. 正式研究的模型配置、费用及授权行为必须明确。入口调整不能隐式触发未授权的收费调用。

入口验收要求：

- 只给公司名称的正式研究请求进入公开资料获取流程，不读取默认演示 manifest。
- 显式演示入口在受控虚构资料下离线运行；无真实网络和模型调用。
- 一个来源失败的受控测试证明正式研究继续查找，并保留失败记录。
- 相关旧任务的恢复、重放及公共引擎行为完成针对性回归；历史证据不被改写。
