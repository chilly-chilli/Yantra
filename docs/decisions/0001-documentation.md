# 0001：文档组织与版本维护

日期：2026-10-13（Asia/Shanghai）。状态：采纳。依据：用户要求整理项目文档并补充工程规范。

## 背景

README承载较多完整操作说明，带版本的使用、验收、提案和任务提示词混在docs根目录。当前说明引用旧版文稿，容易把历史限制或建议当作当前行为。

## 决策

1. README维护项目概览、快速开始和导航；当前使用、能力、估值、知识及架构分别使用稳定文件名。
2. 验证记录按版本放入`docs/validation/<version>/`；历史日志及JSON摘要保持内容与现有路径，新证据随版本归档。
3. 原使用与实施文稿归入`docs/archive/`，提案／审阅归入`docs/proposals/`，原任务提示词归入`docs/prompts/`。
4. 旧文档路径保留短兼容入口，仓库内链接改向明确的当前或历史正文。
5. 功能与文档同步维护；区分已实现、已验证、未验证和接口预留。commit与push的执行规则写入根AGENTS.md。

## 影响

每个主题有明确的主要维护入口。历史内容保留版本、日期、命令、结果和限制；迁移只调整相对链接和历史提示。兼容入口不重复维护正文。源码、测试、运行结果、用户材料和凭据不因此次目录整理而改变。

本次没有追溯创建v0.3代码提交或执行push；当前文档依赖尚未提交的v0.3实现，提交时应保持代码与文档版本一致。
