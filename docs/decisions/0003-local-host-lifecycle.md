# ADR 0003：本地宿主入口与研究进程生命周期

日期：2026-10-15。状态：已采纳，0.5.0（Unreleased）。关联：[ADK原生边界](0002-adk-native-boundaries.md)、[宿主契约](../HOSTS.md)、[验证](../validation/v0.5.0/README.md)。

## 固定能力与缺口

核对已安装 google-adk 2.11.0 的 `Runner.run_async`、`apps.App.resumability_config` 和当前 `run_engine/native_app` 工厂。原生 Runner 提供异步事件迭代、Session、invocation、abort_signal、插件和恢复；生成器完成／调用进程退出不构成可跨宿主连接存活的本机任务队列。原生 at-least-once 恢复也不提供外部收费操作与业务账本的跨事务幂等。

因此保留原 ADK 通用执行链和业务控制器，补充最小本机进程入口。没有升级 ADK、引入分布式平台、复用宿主订阅或更改模型。

## 决策

- `HostService` 只记录提交和操作意图、幂等摘要、执行者观察及安全操作结果。SQLite 不复制费用状态；每项研究的预算、授权、证据和恢复仍由原控制器写入。
- 提交先持久化，再用同一安装环境的 Python、参数数组、独立 session 和脱离调用管道的 stdio 启动执行者。执行者持有独立宿主锁以排除同项研究的两个执行者；原引擎锁继续防止 CLI／ADK 同时写业务状态。进程结束后通过锁和最终意图记录区别 idle／interrupted，不只相信保存的 running 或 PID。
- 查询不重启。明确恢复保留原截止、预算和未知外部操作拒绝规则；机器重启不自动继续。操作收据未落盘而进程退出时，不能推断操作未发生；保留不确定性并拒绝自动覆盖或重放。
- 修改在接受时核对状态修订和 pending 标识，在原引擎锁内再次核对修订。忙时明确拒绝；重复 operation ID 返回原收据。没有建立第二个参数账本或永久授权写入者。
- 新宿主研究的控制器在最终交付时发布不可变成果代次和内容寻址字节。旧 `report-vN` 为兼容输出，新的受承诺历史读取使用不可变索引。成果代次与假设版本分别记录，资格、来源及哈希跟随固定代次。ADK 的既有只读索引与旧运行历史行为保持原样。
- stdio MCP 使用已固定的 Python SDK 1.30.0；schema 复用 Pydantic，不另写一套校验。可信本地客户端显式共享工作区，user/session 参数不能充当认证。宿主没有提交映射的 ADK 已绑定研究继续从原所属 Session 访问。

## 外部行为验收

实际子进程退出后查询、同键并发提交、真实 SIGKILL／恢复、旧修订拒绝、未知操作／过期预算保留、跨入口账本一致、版本篡改／越界拒绝、真实 stdio 重连、干净安装跨目录，以及两宿主的离线研究／读／修改闭环分别记录。真实模型生成、外部资料覆盖、judge 和机器断电没有由这些测试证明，见[限制](../validation/v0.5.0/README.md)。
